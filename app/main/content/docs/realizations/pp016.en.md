# Develop Python AI Agents for a Financial Analysis Application

## Context

Following my experiments in generative artificial intelligence, I undertook the development of agents in Python without systematically relying on orchestration frameworks like LangChain.

My goal was to understand how to directly build the mechanisms necessary for an agent's operation and apply them to a concrete use case: a financial analysis and advisory application.

This project led me to explore a hybrid architecture associating models executed locally with **Ollama** and services accessible via API.

One of the challenges was to consider the distribution of processing based on the nature of the information handled, prioritizing local execution for data considered confidential.

## Objectives

- Develop AI agents directly in Python.
- Understand orchestration mechanisms without relying on a complete agent framework.
- Experiment with using local models with Ollama.
- Integrate services of models accessible via API.
- Design an application applied to financial analysis.
- Deepen my skills in software architecture and agent-based AI.

## Approach and implementation

### 1. Develop Agents in Python without LangChain

I chose to explore the development of agents in Python by freeing myself from a systematic dependency on LangChain.

This approach aims to better understand the interactions between a Python program and a language model.

It also allows for reflection on the responsibilities that the application itself must handle: preparing requests, managing responses, coordinating processing, and controlling execution.

### 2. Experiment with Local Execution using Ollama

I used Ollama as a component of my agent-based approach.

Local execution has particular interest for applications likely to handle personal or confidential information.

It allows considering an architecture in which certain processing is performed on a controlled machine rather than entrusted to a remote service.

However, the use of Ollama alone does not guarantee the confidentiality of the entire application: this also depends on other components and data flows.

### 3. Design a Hybrid Architecture with APIs

I also planned to use APIs for processing non-confidential information.

### 4. Apply agents to a financial use case

I directed these experiments toward the development of a financial advisory application.

This domain constitutes an interesting application area for AI, as it may require combining several categories of information, analyzing them, and producing understandable explanations.

The project aims to explore the possibilities of agents to assist this type of processing.

### 5. Study data separation according to sensitivity

One of the project's structural choices is the distinction between information intended to remain local and information that may be processed by external services.

### 6. Organize development and experiments

The project fits into my software development approach using Python, Git, and GitHub.

## My Role

**I initiated and developed AI agent experiments in Python, then explored their application to a financial advisory project.**

## Technologies and Methods

**Technologies:** Python, Ollama, language models, model APIs, Git, GitHub.

**Concepts:** AI agents, orchestration, LLM, hybrid architecture, local processing, API integration, data separation.

**Methods:** prototyping, modular architecture, data flow analysis, version control.

## Results

- Development of AI agents directly in Python.
- Exploration of an architecture combining local processing and remote services.
- Development of a financial application project.

## Lessons Learned

### 1. Developing without a framework allows for better understanding of orchestration

Building agents directly in Python constitutes a useful approach to understand the responsibilities of an agentic application and master its architecture.

### 2. The choice of a model also depends on its execution mode

Using a local or remote model is not solely a matter of performance considerations. It also raises questions about integration, data control, and operations.

### 3. Confidentiality must be verified in real flows

Simply using a local model is not sufficient to guarantee that no sensitive data leaves the user's environment.

**This project illustrates my transition from experimenting with language models to designing agent-based applications in Python, with a particular focus on software architecture, local execution, and control of exchanges with external services.**
