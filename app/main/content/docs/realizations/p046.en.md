# Develop a Python web application to leverage Quality data

## Context

In an industrial environment, risk analyses FMEA (AMDEC) and control plans are centralized in a reference business application.

While this tool guarantees the management and traceability of information, its interface does not necessarily meet all user consultation and analysis needs: navigating hierarchies, searching for information, filtering control plans, or creating cross-functional summaries.

**Objective: Develop a complementary web application to leverage FMEA data more efficiently, without duplicating the existing business reference.**

## Solution

I designed and developed a web application with **Python and Flask**, fed by FMEA system data via an API.

The architecture is based on three principles:

- **Maintain a single source of truth**: data remains managed in the official FMEA application.
- **Separate data extraction from their presentation**: Python handles retrieval and structuring of information, while Flask provides the web interface.
- **Adapt the user experience to business needs**: offer views, searches, and summaries complementary to those of the reference tool.

The application functions as a consultation and analysis layer. Data modifications are performed in the official system, accessible directly from the interface.

## Technical Development

**1. Data Integration via API**

Development of a Python chain to:

- Query the source platform API.
- Extract data from risk analyses and control plans.
- Structure information for exploitation.
- Prepare data necessary for the application's various views.

**2. Flask Application Development**

Design of a web interface accessible from a browser, integrating several features:

- Structured visualization of FMEA and control plans.
- Navigation and search within FMEA hierarchies.
- Dynamic filters and sorting.
- Cross-functional summaries on business data.
- Direct links to records in the reference system.

**3. Application Distribution**

Creation of an executable version allowing users to launch the application locally, without prior installation of a Python development environment.

This solution facilitated the availability of the prototype and its use by business teams.

**4. Preparation for containerization**

Preparation of a Docker version of the application to study its evolution towards centralized hosting.

This work allowed addressing deployment issues, software dependencies, and integration into the company's IT environment.

My achievements include:

## Results

- Development of a functional web application in Python and Flask.
- Availability of a local version usable by employees.
- Simplification of FMEA and control plan consultation.
- Addition of search and analysis features complementary to the official system.
- Positive user feedback on ease of access to information and time spent on searches.
- Technical preparation for evolution towards a containerized solution.

## Lessons Learned

**Developing a business application is not just about coding features: it requires designing a useful, maintainable solution compatible with the existing information system.**

Three principles emerge from this experience:

- **Leverage existing systems rather than duplicating them**: using an API enriches usage while preserving the official repository.
- **Prototype quickly and validate with users**: a functional application allows validating needs and guiding enhancements based on actual usage.
- **Anticipate scaling**: deploying a prototype implies progressively addressing deployment, security, maintenance, and IT system integration questions.
