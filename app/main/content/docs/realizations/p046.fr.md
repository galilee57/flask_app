# Développer une application web Python pour exploiter les données Qualité

## Contexte

Dans un environnement industriel, les analyses de risques FMEA (AMDEC) et les plans de contrôle sont centralisés dans une application métier de référence.

Si cet outil garantit la gestion et la traçabilité des informations, son interface ne répond pas nécessairement à tous les besoins de consultation et d'analyse des utilisateurs : navigation dans les arborescences, recherche d'informations, filtrage des plans de contrôle ou réalisation de synthèses transverses.

**L'objectif : développer une application web complémentaire permettant d'exploiter plus efficacement les données FMEA, sans dupliquer le référentiel métier existant.**

## Solution

J'ai conçu et développé une application web avec **Python et Flask**, alimentée par les données du système FMEA via une API.

L'architecture repose sur trois principes :

- **Conserver une source unique de vérité** : les données restent gérées dans l'application FMEA officielle.
- **Séparer l'extraction des données de leur restitution** : Python assure la récupération et la structuration des informations, tandis que Flask fournit l'interface web.
- **Adapter l'expérience utilisateur aux besoins métier** : proposer des vues, des recherches et des synthèses complémentaires à celles de l'outil de référence.

L'application fonctionne comme une couche de consultation et d'analyse. Les modifications des données sont réalisées dans le système officiel, accessible directement depuis l'interface.

## Développement technique

**1. Intégration des données via API**

Développement d'une chaîne Python permettant de :

- Requêter l'API de la plateforme source.
- Extraire les données des analyses de risques et des plans de contrôle.
- Structurer les informations pour leur exploitation.
- Préparer les données nécessaires aux différentes vues de l'application.

**2. Développement de l'application Flask**

Conception d'une interface web accessible depuis un navigateur, intégrant plusieurs fonctionnalités :

- Visualisation structurée des FMEA et des plans de contrôle.
- Navigation et recherche dans les arborescences FMEA.
- Filtres et tris dynamiques.
- Synthèses transverses sur les données métier.
- Liens directs vers les enregistrements du système de référence.

**3. Distribution de l'application**

Création d'une version exécutable permettant aux utilisateurs de lancer l'application localement, sans installation préalable d'un environnement de développement Python.

Cette solution a facilité la mise à disposition du prototype et son utilisation par les équipes métier.

**4. Préparation à la conteneurisation**

Préparation d'une version Docker de l'application afin d'étudier son évolution vers un hébergement centralisé.

Ce travail a permis d'aborder les problématiques de déploiement, de dépendances logicielles et d'intégration dans l'environnement informatique de l'entreprise.

## Mon rôle

J'ai assuré directement la conception et le développement technique de l'application.

Mes réalisations comprennent :

- Le développement des scripts Python d'extraction et de préparation des données.
- La conception de l'application web avec Flask.
- L'implémentation des fonctionnalités de recherche, filtrage et visualisation.
- L'intégration de liens vers le référentiel FMEA.
- L'empaquetage de l'application en exécutable.
- La préparation de sa conteneurisation avec Docker.
- Les évolutions fonctionnelles à partir des retours utilisateurs.

J'ai également présenté la solution aux équipes métier et participé aux échanges avec les équipes IT sur les possibilités d'industrialisation.

## Résultats

- Développement d'une application web fonctionnelle en Python et Flask.
- Mise à disposition d'une version locale utilisable par les collaborateurs.
- Simplification de la consultation des FMEA et des plans de contrôle.
- Ajout de fonctionnalités de recherche et d'analyse complémentaires au système officiel.
- Retours utilisateurs positifs sur la facilité d'accès aux informations et le temps consacré aux recherches.
- Préparation technique d'une évolution vers une solution conteneurisée.

## Enseignements

**Développer une application métier ne consiste pas uniquement à coder des fonctionnalités : il faut concevoir une solution utile, maintenable et compatible avec le système d'information existant.**

Trois principes ressortent de cette expérience :

- **Exploiter l'existant plutôt que le dupliquer** : l'utilisation d'une API permet d'enrichir les usages tout en préservant le référentiel officiel.
- **Prototyper rapidement et confronter aux utilisateurs** : une application fonctionnelle permet de valider les besoins et d'orienter les évolutions à partir des usages réels.
- **Anticiper le passage à l'échelle** : la diffusion d'un prototype implique de traiter progressivement les questions de déploiement, de sécurité, de maintenance et d'intégration au SI.

>**Ce projet illustre ma capacité à transformer un besoin métier en application logicielle opérationnelle**, en maîtrisant la chaîne allant de l'acquisition des données au développement de l'interface et à la préparation du déploiement.
