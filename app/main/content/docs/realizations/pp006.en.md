# Develop applications to automate digital content management

## Context

Daily management of digital content involves many repetitive operations: retrieving information, synthesizing it, organizing files, identifying duplicates, or correcting metadata.

To address these needs, I developed two personal applications:

- **YouTube-to-Obsidian**, to transform video content into structured notes.
- **A photo sorting tool**, to organize media files and prepare their import into a photo library.

These two achievements pursue a common goal: automating processing while maintaining structured, traceable, and reusable results.

## Objectives

- Automate the retrieval and transformation of content.
- Reduce repetitive manual handling.
- Structure information to facilitate its reuse.
- Exploit file metadata.
- Preserve source data.
- Handle errors and special situations.
- Systematically structure developments in GitHub repositories.

## Approach and implementation

### 1. Develop YouTube-to-Obsidian

I developed an application to prepare a note from a YouTube video URL.

The processing relies on several steps.

**Information Retrieval**

The application retrieves available metadata and the video transcription.

**Synthesis Generation**

The transcription is sent to a summarization component to produce a structured version of the content.

**Markdown Note Creation**

The result is formatted in a Markdown file intended for use in Obsidian.

**Preservation of Sources**

The application retains metadata and transcripts to enable retrieval of original information.

**Secure Processing**

The pipeline logs its steps and avoids overwriting an existing note without explicit authorization.

This application thus combines data retrieval, text processing, automated synthesis, and document generation.

### 2. Develop a Photo Sorting Tool

I also developed an application designed to facilitate the organization of photo files before their import into a photo library.

The processing relies on information available in the files, notably dates.

The application enables:

- Reading temporal metadata of media.
- Organizing files by date.
- Identifying exact duplicates.
- Preparing a sorting directory structure.
- Managing name collisions.
- Copying files to their destination.

Sorting is designed to work on copies, in order to preserve source files.

### 3. Integrate Metadata Management

The photo management project also includes a separate tool for modifying certain date information.

This feature addresses situations where file metadata is incorrect or incomplete.

Unlike the sorting module, this operation can modify the metadata of the affected files.

A backup is provided by default to limit risks associated with these modifications.

### 4. Design Reliable and Traceable Processes

Both applications rely on particular attention to the reliability of operations.

I integrated mechanisms intended to prevent information loss and unintended modifications:

- Retaining source data for video notes.
- Logging processing steps.
- Protection against overwriting existing notes.
- Detection of exact duplicates.
- Managing name conflicts.
- Sorting via copies.
- Backup before certain metadata modifications.

These choices allow distinguishing the automation of a simple succession of file operations from more complex workflows.

## My Role

**I led the development of these personal applications, from needs identification to tool implementation.**

## Technologies and Methods

**Technologies:** web applications, Python, Markdown, Obsidian, transcript processing, media file metadata.

**Methods:** automation, data processing, file organization, duplicate detection, document generation, logging, error handling.

## Results

### YouTube-to-Obsidian Application

An implementation enables chaining the retrieval of information from a video, processing its transcript, and preparing a Markdown note.

This desktop application was subsequently rewritten in Swift and published on the AppStore (see project)

### Photo Sorting Application

An implementation enables preparing media file organization, identifying exact duplicates, and managing name collisions.

## Lessons Learned

### GitHub is fundamental to any development project

Creating a GitHub repository at the start of a project has become a systematic rule in my development approach.

This discipline enables:

- Securing evolutions and facilitating rollbacks to previous versions.
- Structuring files, documentation, and dependencies.
- Facilitating successive developments and maintenance.
- Working more effectively with development agents such as Codex.

The GitHub repository thus forms the foundation of each application, rather than a formality added at the end of development.

### Targeted tools can effectively address personal needs

A specialized and well-structured application can effectively simplify a specific process without requiring a complex platform.

**These achievements illustrate my ability to design concrete applications, automate content processing, and integrate reliability and traceability mechanisms into my software developments.**
